---
title: "Quickstart"
description: "Mount Hookfish in a Hono app, connect Gmail through MCP, and read your inbox."
---

This guide creates one Hono application. The app mounts `HookfishServer`, calls
it in-process with `Hookfish`, and reads Gmail through
`https://gmail.run.tools`.

## Prerequisites

- Node.js 20 or later
- pnpm
- A Google account with Gmail enabled

You do not need to create a Google OAuth application. Hookfish uses the MCP
server's OAuth discovery metadata and supported client-registration mechanism.

<Steps>
  <Step title="Scaffold and start Hookfish">
    ```bash
    npm i -g hookfish@latest
    hookfish init my-broker --backend node
    cd my-broker
    pnpm dev
    ```

    The generated `src/index.ts` is a Hono application with `HookfishServer`
    mounted at `/api`. The scaffold also registers the trusted `mcp` and
    `secret` providers and creates gitignored `OAUTH_ENCRYPTION_KEY` and
    `HOOKFISH_API_KEY` values. Leave this terminal running.
  </Step>

  <Step title="Add the Gmail route">
    Open another terminal, enter the generated project, and install the SDKs:

    ```bash
    cd my-broker
    pnpm add @hookfish/sdk @modelcontextprotocol/client
    ```

    Replace the generated `src/index.ts` with this application:

    ```ts
    import { serve } from '@hono/node-server'
    import { HookfishServer } from '@hookfish/api'
    import { Hookfish } from '@hookfish/sdk'
    import {
      Client as McpClient,
      StreamableHTTPClientTransport,
    } from '@modelcontextprotocol/client'
    import { Hono } from 'hono'
    import config from '../hookfish.config'

    const apiKey = process.env.HOOKFISH_API_KEY
    if (!apiKey) throw new Error('HOOKFISH_API_KEY is required')

    const port = Number(process.env.PORT ?? 8787)
    const hostname = process.env.HOST ?? '127.0.0.1'
    const backendOrigin = `http://${hostname}:${port}`
    const hookfishServer = await HookfishServer.init(config)
    const app = new Hono()

    app.route('/', hookfishServer)

    const hookfish = new Hookfish({
      apiKey,
      baseUrl: `${backendOrigin}/api`,
      fetch: (input, init) =>
        app.fetch(new Request(input, init), process.env),
    })

    app.get('/inbox', async () => {
      const mcp = new McpClient(
        { name: 'gmail-inbox-quickstart', version: '1.0.0' },
        { versionNegotiation: { mode: 'auto' } },
      )

      try {
        await mcp.connect(
          new StreamableHTTPClientTransport(
            new URL('https://gmail.run.tools'),
            {
              authProvider: {
                token: async () => {
                  const connection = await hookfish.connections.access(
                    'user/personal/gmail/mcp',
                    {
                      configuration: {
                        resource_url: 'https://gmail.run.tools',
                      },
                    },
                  )
                  return connection.secret
                },
                onUnauthorized: async () => {
                  await hookfish.connections.authorize(
                    'user/personal/gmail/mcp',
                  )
                },
              },
            },
          ),
        )

        const inbox = await mcp.callTool({
          name: 'Gmail_SearchEmailsByQuery',
          arguments: {
            query: 'in:inbox',
            max_results: 10,
            result_detail: 'lightweight',
          },
        })

        return new Response(JSON.stringify(inbox), {
          headers: { 'Content-Type': 'application/json' },
        })
      } finally {
        await mcp.close()
      }
    })

    serve({
      fetch: (request) => app.fetch(request, process.env),
      hostname,
      port,
    })

    console.log(`Hookfish backend running at ${backendOrigin}/api/docs`)
    ```

    The custom `fetch` lets `Hookfish` call the mounted server in the same
    process. The scaffold's watch process reloads the application after you
    save the file.
  </Step>

  <Step title="Authorize Gmail and read the inbox">
    Request the inbox:

    ```bash
    curl http://127.0.0.1:8787/inbox
    ```

    The first request returns `401 authorization_required` with a fresh
    `authorize_url`. Open that URL and approve access, then run the `curl`
    command again to receive the inbox result.

    `HookfishError` preserves the failed Hookfish response through Hono. You do
    not need an `onError` handler to retain the status, error code, or
    authorization URL. If the MCP server later rejects the credential,
    `onUnauthorized` starts a fresh authorization flow and the new response
    bubbles through Hono in the same way.
  </Step>
</Steps>

The path `user/personal/gmail/mcp` has four parts:

- Namespace: `user/personal`
- Resource identity: `gmail`
- Provider implementation: `mcp`
- Authentication: OAuth

The final segment selects trusted provider code. The `gmail` identity
distinguishes this generic MCP connection from other resources under the same
namespace. Hookfish stores the URL on first access and rejects a later access
that supplies a different URL for the same path. A concrete Gmail provider at
`user/personal/gmail` is a different connection because its final segment is
`gmail`.

<Warning>
  Keep the `/inbox` route behind your application's authentication before using
  this pattern with real users. Hookfish returns the usable MCP credential only
  to this trusted server code.
</Warning>
