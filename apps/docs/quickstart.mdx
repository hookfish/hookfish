Create a standalone Node.js broker, connect Notion's remote MCP server, and
retrieve the current provider token from trusted server code.

## Prerequisites

- Node.js 20 or later
- pnpm
- A Notion account with access to a workspace you can authorize

You do not need to create a Notion OAuth application. The MCP provider uses
Notion's authorization-server metadata and dynamic client registration.

## Create your broker

<Steps>
  <Step title="Scaffold a Node.js project">
    Run the initializer and enter the generated directory.

    ```bash
    pnpm dlx hookfish init my-broker --backend node
    cd my-broker
    ```

    The initializer installs dependencies and creates a gitignored `.env` with
    a unique `OAUTH_ENCRYPTION_KEY` and `BROKER_API_KEY=test`.
  </Step>

  <Step title="Start the backend and dashboard">
    Run both processes with one command.

    ```bash
    pnpm dev
    ```

    The terminal prints the dashboard URL, normally `http://127.0.0.1:5173`.
    The dashboard proxies `/api` to the generated backend. Use
    `pnpm dev:server` when you only need the backend.
  </Step>

  <Step title="Create the Notion MCP provider">
    In the dashboard, enter the local broker key `test`, then select
    **Add provider**. Choose the MCP template and enter:

    | Field | Value |
    | --- | --- |
    | Configuration ID | `notion-mcp` |
    | Label | `Notion MCP` |
    | Resource URL | `https://mcp.notion.com/mcp` |
    | Credential mode | Register automatically |

    You can perform the same operation from trusted server code:

    ```bash
    curl --request PUT http://127.0.0.1:5173/api/admin/providers/notion-mcp \
      --header 'Authorization: Bearer test' \
      --header 'Content-Type: application/json' \
      --data '{
        "template": "mcp",
        "label": "Notion MCP",
        "configuration": {
          "resource_url": "https://mcp.notion.com/mcp",
          "scopes": []
        },
        "credentials": { "mode": "register" }
      }'
    ```
  </Step>

  <Step title="Start a connection">
    Request an authorization URL from trusted server code.

    ```bash
    curl --request POST http://127.0.0.1:5173/api/oauth/authorize/notion-mcp \
      --header 'Authorization: Bearer test' \
      --header 'Content-Type: application/json' \
      --data '{"connection_id":"personal/notion"}'
    ```

    Open the returned `authorize_url`, sign in to Notion, and approve access.
    Hookfish validates the callback, encrypts the credentials, and stores the
    connection as `personal/notion`.
  </Step>

  <Step title="Retrieve a current provider token">
    After the callback completes, request the token from the backend.

    ```bash
    curl http://127.0.0.1:5173/api/oauth/tokens/personal/notion \
      --header 'Authorization: Bearer test'
    ```

    Hookfish refreshes an expiring token before returning it when the provider
    supports refresh.
  </Step>
</Steps>

<Check>
  You now have a persisted OAuth connection. Your application can refer to it
  as `personal/notion` without storing the provider credentials itself.
</Check>

## Understand the generated project

The default development command runs two processes:

```text
Browser
  │
  ▼
Hookfish dashboard :5173
  │ proxies /api
  ▼
Hookfish backend :8787
  │
  ▼
PGlite data/hookfish
```

The generated `hookfish.config.ts` contains provider factories, database
configuration, callback settings, and documentation visibility. The backend
mounts `Hookfish.init(config).fetch` below `/api`.
