---
title: "Quickstart"
description: "Scaffold a Hookfish backend, add one Hono route, and read a Gmail inbox."
---

This guide scaffolds a Hookfish backend, adds one application route, and reads
a Gmail inbox through `https://gmail.run.tools`. Hookfish handles OAuth,
constructs the authenticated MCP client, and maps connection state to the
route's HTTP response.

Hookfish uses the MCP server's OAuth discovery metadata and supported
client-registration mechanism to complete the connection.

## Prerequisites

- Node.js 20.4 or later
- pnpm
- A Google account with Gmail enabled

<Steps>
  <Step title="Scaffold the application">
    ```bash
    npm i -g hookfish@latest
    hookfish init my-app --backend node
    cd my-app
    ```

    The scaffold creates a Hono application with Hookfish mounted at `/api`.
    It writes gitignored `OAUTH_ENCRYPTION_KEY` and `HOOKFISH_API_KEY` values
    to `.env`, registers the generic `mcp` provider, trusts the backend origin
    for callback returns, and stores local connections in PGlite under
    `data/hookfish`.
  </Step>

  <Step title="Add the inbox route">
    Add the route to the generated `src/index.ts` before the call to `serve`:

    ```ts
    const hookfishServer = await HookfishServer.init(config)
    const hookfish = hookfishServer.client()
    const app = new Hono()

    app.mount(hookfishServer.basePath, hookfishServer.handler)

    app.get('/inbox', async (c) => {
      await using gmail = await hookfish.mcp('user/personal/gmail', {
        resourceUrl: 'https://gmail.run.tools',
        returnTo: 'http://127.0.0.1:8787/inbox',
      })

      return c.json(
        await gmail.callTool({
          name: 'Gmail_SearchEmailsByQuery',
          arguments: { query: 'in:inbox', max_results: 10 },
        }),
      )
    })
    ```

    `basePath` defaults to `/api`. Hookfish uses the same value when it builds
    callback URLs, while `handler` serves the routes relative to that mount.
    Set `basePath: '/hookfish'` in `hookfish.config.ts` to move the API and its
    callbacks together.

    `hookfishServer.client()` gives trusted application routes direct access
    to the embedded broker and its configured provider clients.
  </Step>

  <Step title="Run it">
    ```bash
    pnpm dev:server
    curl -i http://127.0.0.1:8787/inbox
    ```

    The connection is not authorized yet, so the route returns a fresh consent
    URL:

    ```http
    HTTP/1.1 428 Precondition Required
    Content-Type: application/json
    Cache-Control: no-store

    {"error":{"code":"authorization_required",
              "authorize_url":"https://accounts.google.com/o/oauth2/v2/auth?...",
              "expires_at":"2026-08-17T20:10:00.000Z"}}
    ```

    Open `authorize_url` and approve access. Hookfish stores the encrypted
    credential and redirects to `/inbox`. Request the route again to read the
    inbox.
  </Step>
</Steps>

The route opens the Gmail connection as an MCP client, calls the search tool,
and returns its result. Hookfish turns connection states such as required
consent into application responses through Hono's error boundary. See
[how Hookfish works](/concepts/how-it-works) for the request and error flow.

The method appends its configured `mcp` provider ID to the resource namespace:

```text
hookfish.mcp('user/personal/gmail', { resourceUrl })
  → user/personal/gmail/mcp
```

In a real application, derive the namespace from your authenticated session.
See [application authentication](/authentication/application-auth).

<Warning>
  The MCP client receives the usable provider credential and can return
  sensitive Gmail data. Keep `hookfish.mcp()` in trusted server code and
  filter application responses before exposing them to a browser.
</Warning>
