---
title: "Quickstart"
description: "Run Hookfish locally, connect Gmail through MCP, and read an inbox from one TypeScript script."
---

This guide creates a local Hookfish API and calls it from one TypeScript
script. The script completes OAuth for `https://gmail.run.tools`, connects its
MCP client, and prints the Gmail inbox without using the Hookfish dashboard.

## Prerequisites

- Node.js 20 or later
- pnpm
- A Google account with Gmail enabled

You do not need to create a Google OAuth application. Hookfish uses the MCP
server's OAuth discovery metadata and supported client-registration mechanism.

<Steps>
  <Step title="Scaffold and start Hookfish">
    ```bash
    npm i -g hookfish@latest
    hookfish init my-broker --backend node
    cd my-broker
    pnpm dev
    ```

    The scaffold registers the trusted `mcp` and `secret` provider
    implementations and creates gitignored `OAUTH_ENCRYPTION_KEY` and
    `HOOKFISH_API_KEY` values. The Hookfish API listens at
    `http://127.0.0.1:8787/api` by default. Leave this terminal running.
  </Step>

  <Step title="Create the Gmail script">
    Open another terminal, enter the generated project, and install the SDKs:

    ```bash
    cd my-broker
    pnpm add @hookfish/sdk @modelcontextprotocol/client
    ```

    Then create `gmail.ts` in the project root:

    ```ts
    import { Hookfish } from '@hookfish/sdk'
    import {
      Client as McpClient,
      StreamableHTTPClientTransport,
    } from '@modelcontextprotocol/client'
    async function main() {
      if (!process.env.HOOKFISH_API_KEY) {
        throw new Error('HOOKFISH_API_KEY is required')
      }

      const hookfish = new Hookfish({
        apiKey: process.env.HOOKFISH_API_KEY,
        baseUrl: 'http://127.0.0.1:8787/api',
      })
      const mcp = new McpClient(
        { name: 'gmail-inbox-quickstart', version: '1.0.0' },
        { versionNegotiation: { mode: 'auto' } },
      )

      try {
        await mcp.connect(
          new StreamableHTTPClientTransport(
            new URL('https://gmail.run.tools'),
            {
              authProvider: {
                token: async () => {
                  const connection = await hookfish.connections.access(
                    'user/personal/gmail/mcp',
                    {
                      configuration: {
                        resource_url: 'https://gmail.run.tools',
                      },
                    },
                  )
                  return connection.secret
                },
                onUnauthorized: async () => {
                  await hookfish.connections.authorize('user/personal/gmail/mcp')
                },
              },
            },
          ),
        )
        const inbox = await mcp.callTool({
          name: 'Gmail_SearchEmailsByQuery',
          arguments: {
            query: 'in:inbox',
            max_results: 10,
            result_detail: 'lightweight',
          },
        })

        console.dir(inbox, { depth: null })
      } finally {
        await mcp.close()
      }
    }

    await main()
    ```
  </Step>

  <Step title="Run the script">
    Load the generated environment file and run `gmail.ts`:

    ```bash
    node --env-file=.env --import tsx gmail.ts
    ```

    The first run throws a `HookfishError` containing a fresh `authorizeUrl`.
    Open that URL and approve access, then run the command again to print the
    inbox result. If the MCP server later rejects the credential,
    `onUnauthorized` starts a fresh authorization flow and lets the same error
    bubble up.
  </Step>
</Steps>

The path `user/personal/gmail/mcp` has four parts:

- Namespace: `user/personal`
- Resource identity: `gmail`
- Provider implementation: `mcp`
- Authentication: OAuth

The final segment selects trusted provider code. The `gmail` identity
distinguishes this generic MCP connection from other resources under the same
namespace. Hookfish stores the URL on first access and rejects a later access
that supplies a different URL for the same path. A concrete Gmail provider at
`user/personal/gmail` is a different connection because its final segment is
`gmail`.

<Warning>
  Run this script only in a trusted environment. The MCP auth provider obtains
  the usable credential and sends it to the configured MCP server.
</Warning>
