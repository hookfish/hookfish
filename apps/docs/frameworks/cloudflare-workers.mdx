---
title: "Cloudflare Workers"
description: "Run Hookfish on Cloudflare Workers with SQLite Durable Objects."
---

The Cloudflare scaffold stores encrypted credentials in a SQLite-backed Durable Object. It does not require an external database or a separate migration command.

## Create the project

```bash
pnpm dlx hookfish init my-broker --backend cloudflare
cd my-broker
```

The initializer creates `.dev.vars` with a unique local encryption key and `BROKER_API_KEY=test`. Add provider credentials to that file, then start the Worker and packaged dashboard.

```bash
pnpm dev
```

Wrangler persists local Durable Object state automatically. Run only the Worker with `pnpm dev:server`.

## Understand the generated Worker

The generated Worker exports the Durable Object class and selects an object by Hookfish organization. Routes without an organization use the reserved global object.

```ts
import { Hookfish } from '@hookfish/api'
import {
  durableObjects,
  HookfishDurableObject,
} from '@hookfish/database/durable-object'
import {
  createGitHubProvider,
  createLinearProvider,
  createMcpProvider,
  createNotionProvider,
} from '@hookfish/providers'

export { HookfishDurableObject }

const db = durableObjects<Env>((bindings, context) =>
  bindings.HOOKFISH_DB.getByName(context.organization ?? '__global__'),
)
const frontendUrl = process.env.HOOKFISH_FRONTEND_URL ?? 'http://127.0.0.1:5173'

const hookfish = await Hookfish.init<Env>({
  db,
  includeClient: true,
  includeSwagger: true,
  returnTo: frontendUrl,
  trustedOrigins: [frontendUrl],
  organizationRouting: false,
  providerManagement: true,
  providers: (env) => ({
    github: createGitHubProvider({
      clientId: env.GITHUB_CLIENT_ID,
      clientSecret: env.GITHUB_CLIENT_SECRET,
    }),
    linear: createLinearProvider({
      clientId: env.LINEAR_CLIENT_ID,
      clientSecret: env.LINEAR_CLIENT_SECRET,
    }),
    mcp: createMcpProvider(),
    notion: createNotionProvider({
      clientId: env.NOTION_CLIENT_ID,
      clientSecret: env.NOTION_CLIENT_SECRET,
    }),
  }),
})

export default {
  fetch(request, env, context) {
    return hookfish.fetch(request, env, context)
  },
} satisfies ExportedHandler<Env>
```

The generated `wrangler.jsonc` declares the binding and its SQLite storage.

```jsonc
{
  "$schema": "./node_modules/wrangler/config-schema.json",
  "name": "my-broker",
  "main": "./src/index.ts",
  "compatibility_date": "2026-08-11",
  "compatibility_flags": ["nodejs_compat"],
  "observability": {
    "enabled": true
  },
  "durable_objects": {
    "bindings": [
      {
        "name": "HOOKFISH_DB",
        "class_name": "HookfishDurableObject"
      }
    ]
  },
  "exports": {
    "HookfishDurableObject": {
      "type": "durable-object",
      "storage": "sqlite"
    }
  }
}
```

## Generate binding types

Generate `Env` from the Wrangler configuration instead of maintaining a handwritten binding interface.

```bash
pnpm typegen
pnpm typecheck
```

The generated `wrangler-typegen.env` contains variable names without secret values. Rerun `pnpm typegen` whenever a binding changes.

## Store secrets and deploy

Set production credentials through interactive Wrangler prompts.

```bash
pnpm exec wrangler secret put OAUTH_ENCRYPTION_KEY
pnpm exec wrangler secret put BROKER_API_KEY
pnpm exec wrangler secret put GITHUB_CLIENT_ID
pnpm exec wrangler secret put GITHUB_CLIENT_SECRET
pnpm deploy
```

Never place secret values in `wrangler.jsonc` or `wrangler-typegen.env`.
