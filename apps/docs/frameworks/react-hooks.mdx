---
title: "React applications"
description: "Call application-owned Hookfish endpoints from React without exposing server credentials."
---

Your React application should call the authenticated API that already belongs
to your product. That API verifies the session, applies your authorization
policy, and calls Hookfish from trusted server code.

For example, expose an endpoint such as `/api/integrations/connections` using
the pattern in [Application authentication](/authentication/application-auth).
The browser sends its normal session cookie:

```ts
export async function listConnections() {
  const response = await fetch('/api/integrations/connections', {
    credentials: 'include',
  })

  if (!response.ok) {
    throw new Error(`Could not load connections (${response.status}).`)
  }

  return response.json()
}
```

Use this function with your existing state-management or query library:

```tsx
import { useQuery } from '@tanstack/react-query'
import { listConnections } from './integrations-api'

export function GitHubConnections() {
  const connections = useQuery({
    queryKey: ['integrations', 'connections'],
    queryFn: listConnections,
  })

  if (connections.isPending) return <p>Loading connections…</p>
  if (connections.isError) return <p>{connections.error.message}</p>

  return (
    <ul>
      {connections.data.connections.map((connection) => (
        <li key={connection.path}>{connection.path}</li>
      ))}
    </ul>
  )
}
```

Return only fields required by the screen. Provider credentials,
`connections.access()` results, Hookfish broker tokens, and OAuth client
secrets must remain on the server.

The same design works with React Server Components, server actions, tRPC, Hono
RPC, GraphQL, or an existing REST API. Hookfish does not require a particular
browser transport or authentication library.
