---
title: "Dashboard and browser access"
description: "Run the local Hookfish dashboard or add connection management to an existing application."
---

Browser access is optional. Applications can use Hookfish entirely from trusted
server code without mounting a dashboard or adding browser routes.

## Run the packaged dashboard

Generated API-only projects start their backend and the local dashboard
together:

```bash
pnpm dev
```

To inspect an existing Hookfish server, run:

```bash
HOOKFISH_API_KEY="$HOOKFISH_API_KEY" \
  pnpm dlx hookfish serve --backend-url http://127.0.0.1:8787
```

The command binds to loopback and keeps the configured key in server memory. A
root key shows every connection. A downscoped token shows only the paths allowed
by its grant. The browser never receives either credential.

## Add connection management to your application

Use the authentication, routes, and frontend framework your application already
has:

```text
Your browser UI
  → your authenticated application API
  → Hookfish SDK with a server-side credential
  → Hookfish API
```

Your API can expose the operations required by the screen, such as listing
connection metadata, starting authorization, storing a write-only secret, or
disconnecting a connection. It should derive Hookfish paths from the verified
session and return responses shaped for your product.

Do not expose `connections.access()` through a browser route. A successful
access response contains the usable provider credential and must remain in
trusted server code.

See [Application authentication](/authentication/application-auth) for the
server pattern and [React applications](/frameworks/react-hooks) for a generic
browser example. The same approach works with Next.js, TanStack Start, Remix,
React Router, Vue, or an existing mobile application API.
