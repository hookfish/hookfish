---
title: "Dashboard and browser access"
description: "Mount the operator facade in a frontend and expose tenant-safe connection management to your application."
---

Hookfish treats an operator frontend and your product UI as separate security
surfaces. Neither browser bundle receives a broker credential or a stored
provider credential.

## Mount the operator browser facade

Install the Hono facade in a server-rendered frontend:

```bash
pnpm add @hookfish/client hono
```

The frontend mounts `@hookfish/client`, a Hono application that creates an
ephemeral operator session in an `HttpOnly`, `SameSite=Strict` cookie. The Hono
facade injects the broker credential only for explicit connection-management
operations. It does not proxy the raw `/api/*` surface or expose provider-token
retrieval.

The dashboard can list providers and connections, start authorization, store a
new provider secret, and disconnect a connection. A stored secret is write-only:
the response confirms that it was saved but never returns its value.

<Warning>
  The operator facade does not provide user authentication. Keep local
  development on loopback, and put any hosted operator frontend behind SSO or
  another access-control layer.
</Warning>

Use `createHookfishClient` from your server entry and delegate other requests
to the frontend framework. This TanStack Start example does not use server
functions:

```ts
import { randomBytes } from 'node:crypto'
import { createHookfishClient } from '@hookfish/client'
import handler, { createServerEntry } from '@tanstack/react-start/server-entry'

const client = createHookfishClient({
  apiUrl: process.env.HOOKFISH_BACKEND_URL ?? 'http://127.0.0.1:8787',
  apiKey: () => process.env.HOOKFISH_API_KEY,
  frontendOrigin: (request) =>
    process.env.HOOKFISH_FRONTEND_URL ?? new URL(request.url).origin,
  sessionToken: randomBytes(32).toString('base64url'),
  fallback: (request) => handler.fetch(request),
})

export default createServerEntry({
  fetch: (request) => client.fetch(request),
})
```

Set `HOOKFISH_BACKEND_URL` to the separately deployed Hookfish API origin,
`HOOKFISH_API_KEY` to its root broker credential, and `HOOKFISH_FRONTEND_URL`
to the public origin of this frontend. Keep all three values in the server
environment.

The facade adds browser security headers to HTML responses and honors
`X-Forwarded-Proto: https` or `Forwarded: proto=https` when setting the
`Secure` cookie flag behind a trusted TLS-terminating proxy.

## Build a product connection screen

Configure an application auth provider on the Hookfish server:

```text
Browser
  → /api/client with an application session
  → auth provider verifies the user and current tenant
  → Hookfish creates a short-lived tenant-scoped capability
  → raw Hookfish API
```

The safe application API exposes:

```text
GET    /api/client/providers
GET    /api/client/connections
GET    /api/client/connections/{path}
POST   /api/client/connections/{path}/authorize
PUT    /api/client/connections/{path}/secret
DELETE /api/client/connections/{path}
```

Connection paths are relative to the authenticated tenant. Hookfish ignores
browser-supplied tenant identifiers and enforces its internal tenant namespace
on every raw API request.

There is no client operation corresponding to `connections.access()`. The
browser can receive an authorization URL or `{ stored: true }`, but it cannot
retrieve a provider access token, refresh token, API key, OAuth client secret,
or broker credential.

See [Application authentication](/authentication/application-auth) to connect
Better Auth or implement another application auth provider.
