---
title: "Next.js"
description: "Mount Hookfish in a Next.js App Router route handler."
---

Mount Hookfish below `/api` with an optional catch-all App Router route. Hookfish currently uses the Node.js runtime because the local database adapter and provider SDKs depend on Node APIs.

## Install

```bash
pnpm add @hookfish/api @hookfish/database @hookfish/providers
```

## Create the route handler

Create `app/api/[[...path]]/route.ts`.

```ts
import path from 'node:path'
import { Hookfish } from '@hookfish/api'
import { pglite } from '@hookfish/database/pglite'
import config from '../../../hookfish.config'

export const runtime = 'nodejs'
export const dynamic = 'force-dynamic'

const db = pglite(
  process.env.PGLITE_DATA_DIR ?? path.resolve(process.cwd(), 'pgdata'),
)
const hookfishPromise = Hookfish.init({ ...config, db })

const handle = async (request: Request) => {
  const hookfish = await hookfishPromise
  return hookfish.fetch(request, process.env)
}

export {
  handle as DELETE,
  handle as GET,
  handle as HEAD,
  handle as OPTIONS,
  handle as PATCH,
  handle as POST,
  handle as PUT,
}
```

Adjust the relative import for `hookfish.config.ts` to match your project structure.

## Add application authentication

Pass an `authorizeBrowserRequest` function as the second argument to `Hookfish.init`. Validate your Next.js application session there before allowing `/api/client` requests.

<Note>
  PGlite is suitable for local development and a single persistent Node process. Use Postgres when your Next.js deployment runs multiple instances or uses ephemeral filesystems.
</Note>
