---
title: "Remote MCP servers"
description: "Create per-connection MCP configuration with OAuth discovery, CIMD, PKCE, and DCR fallback."
---

The trusted `mcp` provider turns any compatible Streamable HTTP endpoint into a
connection. There are no runtime provider records to create.

## Register the implementation

```ts
import { createMcpProvider } from '@hookfish/providers'

export default defineHookfishConfig({
  db,
  providers: {
    mcp: createMcpProvider(),
  },
})
```

## Access a remote server

```ts
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/client'

const mcpUrl = new URL('https://mcp.notion.com/mcp')
const authProvider = hookfish.connections.mcpAuthProvider(
  'user/personal/notion/mcp',
  {
    url: mcpUrl.href,
    scopes: [],
    returnTo: 'https://app.example.com/integrations',
  },
)

const transport = new StreamableHTTPClientTransport(mcpUrl, { authProvider })
```

The provider calls Hookfish before each MCP request. When the MCP server returns
`401`, it starts fresh authorization and lets Hookfish's direct
`authorization_required` error bubble to your application error handler.

The path ends in `mcp` because `mcp` is the provider implementation. The
preceding `user/personal/notion` segments are the namespace. This cannot collide
with a fixed Notion connection at `user/personal/notion`, whose provider ID is
`notion`.

The first access stores the normalized URL and scopes. Reusing the path with a
different URL returns `connection_configuration_conflict`.

## Client identity order

Hookfish discovers protected-resource and authorization-server metadata,
requires PKCE S256, and then selects a client mechanism:

1. Use fixed MCP client credentials supplied in deployment configuration.
2. Use the deployment-level HTTPS Client ID Metadata Document when the server
   advertises CIMD support.
3. Use Dynamic Client Registration as a compatibility fallback.

The public CIMD URL is:

```text
https://broker.example.com/api/connections/client-metadata.json
```

CIMD is stateless and shared at the deployment level. If DCR is required, the
resulting client ID and encrypted client secret belong to the individual
connection. Hookfish does not create a reusable runtime provider record.

## Discovery requirements

The MCP resource must publish protected-resource metadata naming an
authorization server. The authorization server must advertise an issuer,
authorization endpoint, token endpoint, and PKCE S256. Hookfish validates a
callback issuer when it is present.

<Info>
  Every unready access returns a newly generated authorization URL.
  `mcpAuthProvider` also handles a credential rejected before its recorded
  expiration.
</Info>
