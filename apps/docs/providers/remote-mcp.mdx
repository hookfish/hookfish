---
title: "Remote MCP servers"
description: "Use fixed typed MCP clients or dynamic per-connection MCP configuration."
---

MCP is a resource protocol, not an authentication kind. Hookfish can bind one
trusted provider ID to a fixed MCP URL or keep the URL as dynamic connection
configuration.

## Fixed MCP provider

Use a fixed provider when the application knows the MCP server at deployment
time:

```ts
import { defineHookfishConfig } from '@hookfish/api'
import { createMcpProvider } from '@hookfish/providers'

export default defineHookfishConfig({
  db,
  providers: {
    notion: createMcpProvider({
      resourceUrl: 'https://mcp.notion.com/mcp',
    }),
  },
})
```

The provider ID contributes a typed method to the in-process client:

```ts
const hookfish = hookfishServer.client()

await using notion = await hookfish.notion('user/personal')

const tools = await notion.listTools()
```

`hookfish.notion()` eagerly calls `connections.access()` for
`user/personal/notion`, then connects the MCP client with the returned access
token. Initial consent errors reach your application before the MCP SDK can
wrap them.

The resource URL lives only in trusted provider configuration. Callers supply
the namespace, not a URL or provider path segment, so
`connection_configuration_conflict` is unreachable through this method.

When the MCP server later returns `401`, the transport starts fresh Hookfish
authorization. `HookfishError.from()` preserves a Hookfish error even when the
transport wraps it in a `cause` chain.

## Dynamic MCP provider

Use the dynamic form when users or another trusted registry choose MCP servers
at runtime:

```ts
providers: {
  mcp: createMcpProvider(),
}
```

Because `mcp` is the key of a static provider map, it contributes a typed
generic method. Supply the resource URL when the application opens the
connection:

```ts
await using notion = await hookfish.mcp('user/personal/notion', {
  resourceUrl: 'https://mcp.notion.com/mcp',
})

await notion.listTools()
```

The final `mcp` segment selects the trusted dynamic provider. The preceding
`notion` segment identifies this resource below `user/personal`. The first
access stores the normalized URL. Reusing the path with a different URL
returns `connection_configuration_conflict`.

Use `connections.access()` directly when the server configuration is not
available, such as from a remote Hookfish SDK client:

```ts
const { secret } = await hookfish.connections.access(
  'user/personal/notion/mcp',
  {
    configuration: {
      resource_url: 'https://mcp.notion.com/mcp',
    },
  },
)
```

If the authorization server omits a requested provider scope, later access
returns `scope_not_granted`. Hookfish does not restart consent automatically
for a scope the provider already declined.

## Supplied credentials

An MCP transport can also read a supplied bearer token from a dynamic `secret`
connection:

```ts
const authProvider = {
  token: async () =>
    (
      await hookfish.connections.access(
        'user/personal/notion-api-key/secret',
      )
    ).secret,
}
```

For a server that expects another header, access the same secret and inject it
through the transport request options:

```ts
const { secret } = await hookfish.connections.access(
  'user/personal/notion-api-key/secret',
)
const transport = new StreamableHTTPClientTransport(mcpUrl, {
  requestInit: { headers: { 'X-API-Key': secret } },
})
```

## Client identity order

Hookfish discovers protected-resource and authorization-server metadata,
requires PKCE S256, and selects a client mechanism:

1. Use fixed MCP client credentials supplied in deployment configuration.
2. Use the deployment-level HTTPS Client ID Metadata Document when advertised.
3. Use Dynamic Client Registration as a compatibility fallback.

The public CIMD URL is:

```text
https://broker.example.com/api/connections/client-metadata.json
```

CIMD is stateless and shared at the deployment level. If DCR is required, the
resulting client credentials belong to the connection and are encrypted before
storage.
