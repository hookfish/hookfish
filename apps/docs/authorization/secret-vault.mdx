---
title: "Secret vault"
description: "Store non-OAuth credentials under the same resource scopes as Hookfish connections."
---

The Hookfish secret vault stores API keys and other non-OAuth credentials under the same hierarchical resource paths used by broker access tokens.

## Store a secret

```bash
curl --request PUT http://127.0.0.1:8787/api/secrets/acme/browserbase/api-key \
  --header "Authorization: Bearer $BROKER_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"value":"<secret-value>"}'
```

Secret values are encrypted with `OAUTH_ENCRYPTION_KEY` before they are stored.

## Retrieve a secret

Only trusted server code should request decrypted values.

```bash
curl http://127.0.0.1:8787/api/secrets/acme/browserbase/api-key \
  --header "Authorization: Bearer $BROKER_API_KEY"
```

`GET /api/secrets?path_prefix=acme` lists accessible paths and timestamps without returning values.

Scoped broker tokens may access only secret paths covered by their resource scopes. Paths below `__hookfish/` are reserved for Hookfish's internal provider credentials.

<Warning>
  Secret-vault operations are excluded from the browser facade. Retrieve values only from trusted server code and do not log response bodies.
</Warning>
