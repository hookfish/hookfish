---
title: "Secret vault"
description: "Store API keys and non-OAuth credentials under Hookfish resource scopes."
---

The vault stores non-OAuth credentials under the same hierarchical paths used
by connections, dynamic providers, and scoped broker tokens.

## Store a secret

```bash
curl --request PUT http://127.0.0.1:8787/api/secrets/acme/browserbase/api-key \
  --header "Authorization: Bearer $BROKER_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"value":"<secret-value>"}'
```

Hookfish encrypts the value with `OAUTH_ENCRYPTION_KEY` before writing it to the
database.

## List metadata

List paths and timestamps without returning decrypted values:

```bash
curl "http://127.0.0.1:8787/api/secrets?path_prefix=acme" \
  --header "Authorization: Bearer $BROKER_API_KEY"
```

Prefix matching respects path-segment boundaries. A prefix of `acme/tools`
does not match `acme/toolsmith`.

## Retrieve and delete a value

Only trusted server code should retrieve decrypted values.

```bash
curl http://127.0.0.1:8787/api/secrets/acme/browserbase/api-key \
  --header "Authorization: Bearer $BROKER_API_KEY"

curl --request DELETE \
  http://127.0.0.1:8787/api/secrets/acme/browserbase/api-key \
  --header "Authorization: Bearer $BROKER_API_KEY"
```

Scoped broker tokens can access only paths covered by their resource scopes.
Paths below `__hookfish/` are reserved for encrypted dynamic-provider
credentials.

<Warning>
  Keep vault operations in authenticated server routes. Do not return secret
  values to browser code or log response bodies.
</Warning>
