---
title: "Application authentication"
description: "Authenticate users before calling Hookfish from trusted server code."
---

Hookfish authenticates broker credentials, not your end users. Keep Auth.js,
Clerk, Auth0, Supabase Auth, or your existing session system in the application.

```text
Browser
  → authenticated application route
  → user and tenant authorization
  → scoped server-side Hookfish SDK
  → Hookfish
```

## Protect the route

```ts
app.use('/integrations/*', async (ctx, next) => {
  const user = await authenticateRequest(ctx.req.raw)
  if (!user) return ctx.json({ error: 'Sign in required.' }, 401)
  ctx.set('user', user)
  await next()
})
```

Map the authenticated identity to a connection namespace in server code. Do
not accept an arbitrary path from the browser.

## Access a connection

```ts
import { Hookfish, HookfishError } from '@hookfish/sdk'

app.onError((error) => {
  if (
    error instanceof HookfishError &&
    error.code === 'authorization_required'
  ) {
    return Response.json(
      {
        error: error.code,
        authorize_url: error.authorizeUrl,
        expires_at: error.expiresAt,
      },
      { status: 401 },
    )
  }
  console.error(error)
  return new Response('Internal Server Error', { status: 500 })
})

app.post('/integrations/github', async (ctx) => {
  const user = ctx.get('user')
  const hookfish = new Hookfish({
    apiKey: await scopedBrokerTokenFor(user.organizationId),
    baseUrl: process.env.HOOKFISH_URL + '/api',
    organization: user.organizationId,
  })
  const path = `user/${user.id}/github`

  const { secret } = await hookfish.connections.access(path)
  return ctx.json(await loadGitHubProfile(secret))
})
```

The browser may receive the authorization URL and the application-level result.
It must never receive `secret`, a broker token, refresh token, or OAuth client
secret.

Use an exact resource scope for one connection or an explicit `/**` scope for
the user's namespace. Application authentication and Hookfish scopes enforce
different boundaries; use both.
