---
title: "Application authentication"
description: "Authenticate users before calling Hookfish from trusted server code."
---

Hookfish authenticates broker credentials, not your end users. Keep Auth.js,
Clerk, Auth0, Supabase Auth, or your existing session system in the application.

```text
Browser
  → authenticated application route
  → user and tenant authorization
  → scoped in-process Hookfish client
  → provider SDK client
```

## Protect the route

```ts
app.use('/integrations/*', async (c, next) => {
  const user = await authenticateRequest(c.req.raw)
  if (!user) return c.json({ error: 'Sign in required.' }, 401)
  c.set('user', user)
  await next()
})
```

Map the authenticated identity to a connection namespace in server code. Do
not accept an arbitrary namespace or connection path from the browser.

## Use a scoped provider client

```ts
app.get('/integrations/github/profile', async (c) => {
  const user = c.get('user')
  const token = await scopedBrokerTokenFor(user.organizationId)
  const hookfish = hookfishServer.client({ token })
  const github = await hookfish.github(
    `organizations/${user.organizationId}/users/${user.id}`,
  )

  const profile = await github.request('GET /user')
  return c.json(profile.data)
})
```

The scoped broker token limits Hookfish access to the tenant namespace. The
provider method appends `/github`, acquires the provider access token, and
constructs Octokit. The browser never receives either token.

If the connection needs consent, `hookfish.github()` throws
`HookfishAuthorizationRequiredError`. Hono's default error handler returns a
non-cacheable `428` response with the fresh authorization URL. Your own missing
session response remains `401`.

Calls on the returned Octokit client retain Octokit's native error behavior.
Hookfish only normalizes errors raised while acquiring the connection.

Use an exact resource scope for one connection or an explicit `/**` scope for
the user's namespace. Application authentication and Hookfish resource scopes
enforce different boundaries; use both.

## Return consent inline

Catch the narrowed error when the application wants to render its own connect
control instead of returning `428`:

```ts
import { HookfishAuthorizationRequiredError } from '@hookfish/api'

try {
  const github = await hookfish.github(namespace)
  return c.json((await github.request('GET /user')).data)
} catch (error) {
  if (error instanceof HookfishAuthorizationRequiredError) {
    return c.json({ authorize_url: error.authorizeUrl })
  }
  throw error
}
```

Return only the authorization URL and application-level result. Never return a
provider access token, broker token, refresh token, or OAuth client secret.
