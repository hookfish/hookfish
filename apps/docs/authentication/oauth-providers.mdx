---
title: "Trusted providers"
description: "Configure OAuth and supplied-secret provider implementations."
---

A provider is trusted application code selected by the final segment of a
connection path. Request bodies cannot choose a template or upload provider
credentials.

## Configure providers

```ts
import { defineHookfishConfig } from '@hookfish/api'
import {
  createGitHubProvider,
  createLinearProvider,
  createMcpProvider,
  createNotionProvider,
  createSecretProvider,
} from '@hookfish/providers'

export default defineHookfishConfig({
  db,
  providers: {
    github: createGitHubProvider({
      clientId: process.env.GITHUB_CLIENT_ID,
      clientSecret: process.env.GITHUB_CLIENT_SECRET,
    }),
    linear: createLinearProvider(),
    mcp: createMcpProvider(),
    notion: createNotionProvider({
      clientId: process.env.NOTION_CLIENT_ID,
      clientSecret: process.env.NOTION_CLIENT_SECRET,
    }),
    secret: createSecretProvider(),
  },
})
```

A static map preserves its provider keys in the client type. GitHub, Linear,
and Notion entries contribute methods that return their official SDK clients:

```ts
const hookfish = hookfishServer.client()

const github = await hookfish.github('user/personal')
const linear = await hookfish.linear('user/personal')
const notion = await hookfish.notion('user/personal')
```

Each method appends its map key to the namespace and eagerly acquires the
connection before constructing the SDK client. Calls on the returned client
retain that SDK's native errors.

Provider IDs must be non-reserved lower-camel JavaScript identifiers up to 128
characters. Slashes, hyphens, dots, and reserved words such as `class` are not
allowed. IDs also cannot collide with Hookfish client members such as
`connections`, `stats`, `client`, or `then`.

## Register callback URLs

Fixed OAuth providers use:

```text
https://broker.example.com/api/connections/callback/github
https://broker.example.com/api/connections/callback/notion
```

Set `OAUTH_REDIRECT_BASE_URL` to the public origin in production. The same
deployment-level callback uses the configured provider ID. A fixed `gmail`
provider ends in `/gmail`; the dynamic `mcp` provider ends in `/mcp`.

## Authentication and provider inputs

`GET /connections/providers` describes credential acquisition and provider
inputs. The `authentication` value is either `oauth` or `secret`. Each input
field declares how its value is used: `identity` adds a path segment,
`configuration` supplies immutable non-secret connection configuration, and
`scopes` requests OAuth scopes.

GitHub, Linear, and Notion use OAuth and expose an optional scopes input but no
connection-specific configuration. The generic `mcp` provider uses OAuth and
requires a resource name and URL, with optional scopes. The generic `secret`
provider requires a credential name and a supplied value. The secret value is
written through `connections.setSecret()` and is never provider configuration
or listable metadata.

The `mcp` provider stores its URL as immutable connection configuration.
Requested and granted OAuth scopes are tracked separately and can change only
through the authorization lifecycle.

Bind a URL in trusted configuration to turn a generic MCP implementation into
a fixed typed provider:

```ts
providers: {
  gmail: createMcpProvider({
    resourceUrl: 'https://gmail.run.tools',
  }),
}
```

This contributes `hookfish.gmail(namespace)`. The fixed URL never appears in a
connection access request.

The generic map entry also contributes a method, but accepts the URL when the
application opens a connection:

```ts
await using notion = await hookfish.mcp('user/personal/notion', {
  resourceUrl: 'https://mcp.notion.com/mcp',
})
```

A lazy `ProviderSource` remains available for large application-owned catalogs.
It resolves trusted provider code by ID; it is not a public provider CRUD
system. Provider factories and lazy sources expose the universal `connections`
surface rather than config-derived methods because their provider set depends
on runtime bindings.
