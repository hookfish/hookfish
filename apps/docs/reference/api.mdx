The running deployment publishes its OpenAPI 3.1 contract at
`/api/openapi.json` and Swagger UI at `/api/docs`.

Send a root or scoped broker credential on authenticated server requests:

```http
Authorization: Bearer <broker-credential>
```

## Connections

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/connections/access/{connection_path}` | Return a secret or `authorization_required` |
| `POST` | `/api/connections/authorize/{connection_path}` | Start fresh authorization unconditionally |
| `PUT` | `/api/connections/secret/{connection_path}` | Set or rotate a static provider secret |
| `GET` | `/api/connections` | List metadata |
| `GET` | `/api/connections/entry/{connection_path}` | Get metadata |
| `DELETE` | `/api/connections/entry/{connection_path}` | Revoke and delete |
| `GET` | `/api/connections/providers` | List trusted provider implementations |
| `GET` | `/api/connections/callback/{provider_id}` | Complete OAuth; public |
| `GET` | `/api/connections/client-metadata.json` | Publish deployment CIMD; public |

An access body may contain:

```json
{
  "url": "https://gmail.run.tools",
  "scopes": [],
  "return_to": "https://app.example.com/integrations"
}
```

`url` is accepted by the trusted `mcp` provider. Provider selection always
comes from the final path segment, never the body.

## Broker administration and generic vault

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/admin/tokens` | Mint a named scoped broker token |
| `GET` | `/api/admin/tokens` | List active token names; root only |
| `DELETE` | `/api/admin/tokens/{name}` | Revoke a token; root only |
| `GET` | `/api/secrets` | List generic vault metadata |
| `PUT` | `/api/secrets/{secret_path}` | Store a generic encrypted value |
| `GET` | `/api/secrets/{secret_path}` | Retrieve a generic encrypted value |
| `DELETE` | `/api/secrets/{secret_path}` | Delete a generic encrypted value |

## Browser facade

The optional `/api/client` facade exposes runtime stats, provider and
connection metadata, and disconnect. It rejects access, `setSecret`, generic
vault values, callbacks, and administration because successful access may
contain a credential.

Connection access responses set `Cache-Control: no-store`. List and get
responses never include stored secrets, refresh tokens, OAuth client secrets,
or bearer values.
