---
title: "Production security"
description: "Review Hookfish credential boundaries, path scopes, and frontend controls."
---

Hookfish encrypts stored credentials and enforces broker scopes. Your host
application still owns identity-provider configuration, key custody, backups,
and operator access.

## Production checklist

- Generate independent high-entropy `OAUTH_ENCRYPTION_KEY` and
  `HOOKFISH_API_KEY` values.
- Store every secret in the runtime's secret manager.
- Set `OAUTH_REDIRECT_BASE_URL` to the public HTTPS callback origin.
- Leave `rawApiOrigins` empty unless a server-to-server deployment requires
  cross-origin raw API access.
- Keep the Hookfish API and every broker credential in trusted server code.
- Verify the application session and permissions before deriving a Hookfish
  resource path.
- Give services scoped, expiring broker tokens instead of the root key.
- Export lifecycle events with `subject` and `basePath` to an audit system.
- Back up the database and encryption key through separate controlled systems.

## Credential boundaries

| Credential | Where it may exist |
| --- | --- |
| Broker root or downscoped token | Trusted server code only |
| Application session cookie or token | Your application |
| Scoped broker token | Authorized application service to Hookfish API only |
| Provider credential | Encrypted broker storage and trusted server operations only |

No browser-facing response contains a provider access token, refresh token,
stored API key, OAuth client secret, application capability, or broker token.

## Path isolation

Your application verifies the session and resolves a canonical base path before
calling Hookfish. Construct every resource path beneath that base, and use a
`basePath/**` broker token when you need enforcement at the Hookfish boundary.

Paths are not rewritten. If `resolveBasePath` returns `organizations/acme`, the
connection remains `organizations/acme/team/github` in the browser-safe API,
raw API, database, OAuth state, and audit events.

A root or downscoped token remains server-side, and the Hookfish API remains the
authority for every operation. Never place either credential in an untrusted
frontend.

## Network boundary

The raw `/api/*` server emits no CORS headers by default. `rawApiOrigins` is a
separate exact-origin allowlist and does not weaken bearer authentication.

Application-owned browser endpoints should use the same origin, session, and
CSRF protections as the rest of your application.

`hookfish serve` binds the first-party Start frontend to loopback and keeps its
API key server-side. Use Better Auth, Clerk, WorkOS, Auth0, or another verified
provider for a remotely hosted frontend.

## Database and key recovery

Database backups without `OAUTH_ENCRYPTION_KEY` cannot restore encrypted
credentials. Changing that key without re-encrypting existing rows makes those
rows unreadable. Keep tested, access-controlled copies of both inputs.

<Warning>
  Never log connection-access responses, authorization headers, callback codes,
  application capabilities, or encryption keys.
</Warning>
