title: "Configuration"
description: "Reference Hookfish broker, application auth, callback, and runtime options."
---

```ts
import { defineHookfishConfig } from '@hookfish/api'
import { betterAuth } from '@hookfish/auth-better-auth'
import { auth } from './auth'

export default defineHookfishConfig({
  db,
  providers,
  auth: betterAuth(auth),
  includeSwagger: false,
  returnTo: 'https://app.example.com/settings/integrations',
  trustedOrigins: ['https://app.example.com'],
  onEvent: async (event) => auditLog.write(event),
})
```

| Option | Default | Purpose |
| --- | --- | --- |
| `db` | Required in self-hosted mode | Ready, promised, or request-aware database |
| `providers` | Required in self-hosted mode | Trusted provider map, registry, source, or factory |
| `backend` | Required in managed mode | OAuth-only `HookfishBackend` supplied instead of `db` and `providers` |
| `auth` | Unset | Authenticate an application user and assert their current tenant |
| `clientOrigins` | `[]` | Additional exact origins allowed to call `/api/client` |
| `includeSwagger` | `true` | Serve `/api/openapi.json` and `/api/docs` |
| `returnTo` | Completion page | Fixed post-callback destination |
| `trustedOrigins` | `[]` | Allow per-authorization `return_to` destinations |
| `rawApiOrigins` | `[]` | Exceptional exact origins allowed to call the raw API with CORS |
| `onEvent` | Unset | Receive best-effort lifecycle and audit events |

Choose exactly one connection configuration:

- `{ db, providers }` makes Hookfish own OAuth state, encrypted tokens, and
  static-secret connections.
- `{ backend: new HookfishBackend(adapter) }` delegates OAuth connections to a
  managed service. This mode does not accept `db` or `providers`.

```ts
import { createHookfish } from '@hookfish/api'
import { HookfishBackend } from '@hookfish/backend'

const hookfish = await createHookfish({
  auth,
  backend: new HookfishBackend(arcadeAdapter),
})
```

Managed backends cannot store static secrets and do not mount the
database-backed `/admin/tokens` routes. See [managed OAuth
backends](/deployment/managed-oauth-backends) for the lifecycle contract.

Supplying `auth` mounts the application-facing API at `/api/client`. Hookfish
does not mount that API without an auth provider. The auth provider returns a
verified application subject and tenant. Hookfish creates a short-lived,
tenant-scoped capability for each request and never sends it to the browser.

`trustedOrigins`, `clientOrigins`, and `rawApiOrigins` are separate controls.
Redirect trust does not grant raw API access. Origin entries must include the
scheme and port, when present. Wildcards are rejected for raw API access.

There is no provider-management switch. Provider implementations are trusted
deployment code. Providers declare `oauth` or `secret` authentication plus a
small input schema for connection identity and non-secret configuration.

## Runtime options

The second argument to `createHookfish` or `HookfishServer.init` accepts
`runtime`, `clientOrigins`, and `rootApiKey`. Most deployments should let
Hookfish resolve `HOOKFISH_API_KEY` from server bindings instead of passing
`rootApiKey` directly.

Use a provider factory when credentials come from request bindings. Use a lazy
`ProviderSource` for a large application-owned catalog while keeping provider
IDs and implementations trusted.
