---
title: "Static secrets"
description: "Store and access API keys through a trusted secret provider."
---

Static API keys use the same connection access API as OAuth credentials. Add a
trusted provider named `secret` to your deployment:

```ts
import { defineHookfishConfig } from '@hookfish/api'
import { createSecretProvider } from '@hookfish/providers'

export default defineHookfishConfig({
  db,
  providers: {
    secret: createSecretProvider(),
  },
})
```

## Store and access a key

```ts
import { Hookfish } from '@hookfish/sdk'

const hookfish = new Hookfish({
  apiKey: process.env.HOOKFISH_API_KEY!,
  baseUrl: 'http://127.0.0.1:8787/api',
})

await hookfish.connections.setSecret(
  'service/prod/openai/secret',
  'sk-example',
)

const { secret: apiKey } = await hookfish.connections.access(
  'service/prod/openai/secret',
)
```

The final `secret` segment selects trusted provider code. The namespace is
`service/prod/openai`. Hookfish encrypts the value before storing it and marks
successful access responses `no-store`.

Calling `setSecret` for an OAuth-backed provider returns an error. Calling
`access` before a static value is stored returns `secret_required`; it does not
return an OAuth URL.

## Generic vault

The separate `hookfish.secrets` API remains available for compatibility but is
no longer exposed in the packaged dashboard. Prefer `connections.setSecret`
and `connections.access()` for new integrations. Public API and SDK removal
will happen only in a separately documented breaking change.

<Warning>
  Store and access secrets only in trusted server code. Connection metadata
  routes and the browser facade never include the value.
</Warning>
