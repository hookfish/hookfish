---
title: "Resource scopes and provider scopes"
description: "Separate Hookfish path authorization from upstream permissions."
---

Hookfish uses two independent scope systems.

## Resource scopes

A broker resource scope grants either one exact path or an explicit subtree:

```text
user/personal/gmail
user/personal/**
**
```

`user/personal/gmail` grants only that exact connection. It does not grant
`user/personal/gmail/mcp`. `user/personal/**` grants the namespace itself and
all descendants. Use `**` only for root-level administration.

This distinction lets a service receive access to one connection without
automatically receiving every connection below a similarly named folder.

## Provider scopes

Provider scopes control what an upstream OAuth credential may do:

```ts
await hookfish.connections.access('acme/engineering/github', {
  scopes: ['read:user', 'repo'],
})
```

The provider implementation defines these values. For MCP, scopes supplied
with the resource URL become the connection's immutable MCP configuration and
the requested upstream permissions.

| Question | Controlled by |
| --- | --- |
| Which Hookfish paths may this service access? | Broker resource scopes |
| Which upstream operations may the secret perform? | Provider scopes |
| Which tenant owns the row? | Organization routing and application auth |

See [Token scoping](/authorization/token-scoping) for delegation and expiry.
