---
title: "How Hookfish works"
description: "Understand the connection lifecycle, API surfaces, and runtime responsibilities."
---

Hookfish sits between your application and OAuth providers. Your application refers to a linked account by a stable connection ID instead of storing provider credentials itself.

## Connection lifecycle

<Steps>
  <Step title="Start authorization">
    Trusted server code calls `POST /api/oauth/authorize/{provider}` with a connection ID or connection ID prefix.
  </Step>
  <Step title="Collect consent">
    Hookfish returns an `authorize_url`. Your application redirects the user to that URL.
  </Step>
  <Step title="Complete the callback">
    The provider redirects to Hookfish. Hookfish validates the single-use state, exchanges the code, and encrypts the returned tokens.
  </Step>
  <Step title="Use the connection">
    Trusted server code calls `GET /api/oauth/tokens/{connection_id}`. Hookfish refreshes the token when necessary before returning it.
  </Step>
  <Step title="Disconnect">
    Hookfish asks the provider to revoke access when supported, then removes the local connection.
  </Step>
</Steps>

Reauthorizing the same connection ID for the same provider replaces its stored credentials. Reusing the ID for a different provider returns `409`.

## API surfaces

| Surface | Audience | Contains secrets |
| --- | --- | --- |
| `/api/*` | Trusted server code | Yes. Includes provider-token retrieval, secret storage, and administration. |
| `/api/client/*` | Authenticated browser clients | No. Only allowlisted connection-management operations are forwarded. |
| `/api` | Developers | Swagger UI for the configured API surface. |
| `/api/openapi.json` | Tools and generated clients | OpenAPI document for the configured API surface. |

The browser facade replaces the browser's headers with a server-side broker credential. Configure `authorizeBrowserRequest` before using it in production.

<Warning>
  The browser facade is not an identity system. Your application must authenticate the request and decide whether the caller may manage connections.
</Warning>

## Portable runtime

`Hookfish.init(config)` returns a Fetch-compatible request handler. Framework adapters only translate their request model into Fetch requests or mount the handler at `/api`.

- Hono on Node.js passes Fetch requests directly.
- Next.js exports the same handler from an App Router catch-all route.
- Express uses the Hono Node request listener adapter.
- Cloudflare Workers pass runtime bindings and an execution context to the handler.

The database follows the same pattern. The generated Node.js, Bun, and Docker backends use PGlite. Vercel uses PGlite locally and Postgres through `DATABASE_URL` when deployed. Cloudflare Workers use SQLite Durable Objects.
